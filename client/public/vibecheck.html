hasBeenActive is the gate that silently swallows the pump buzz. It is false until you tap this page, and the browser refuses to vibrate while it is false.

1 · Buzz on tap

Proves the motor works and is not disabled by Silent or Do Not Disturb. If this does nothing, no web page on this phone can ever buzz and the problem is below the browser.

2 · Buzz from a timer, after a tap

Keep the screen on and watch. This is the pump's exact code path — a setInterval firing the buzz — with activation already granted by the tap that started it. This is what a working pump alert looks like.

3 · Buzz from a timer, with no tap

Tap once to arm, then pull down to reload the page and do not touch the screen again. The timer restarts on load with no activation — which is the state the app is in when Android relaunches it straight onto the Baby tab. If test 2 buzzes and this does not, sticky activation is the whole answer.

4 · Buzz with the screen off

Expected to fail, and recorded so it is not re-investigated. The spec requires the page to be visible; a locked phone cannot be buzzed by a web page at all.

5 · Buzz via a notification

The decisive one. This rides Android's ring & notification vibration channel instead of the touch-feedback channel navigator.vibrate uses. If test 1 stays dead and this buzzes, the Vibration API is simply not available to this phone and the pump alert has to be a notification. Registers a worker of its own, so it does not need the app.
